ExpenseHub BI Publisher reports: setup pack

ExpenseHub reads its master data and payment status from Oracle Fusion through seven BI Publisher reports. This pack contains the SQL for each one and the steps to create, secure and test them. Build them in the test pod first, then move them to production with Archive/Unarchive.

For: the Fusion administrator / BI developer Version 3 · 23 Oct 2026: rates report added; supplier linked by EMPLOYEE_ID; QuickPay totals Catalog folder: /Custom/ExpenseHub

1Before you start: values to fill in

The SQL has placeholders written as <<…>> and marked EDIT. Replace each one with your pod's real value. Items marked VERIFY are the usual Fusion table or column names; check them in your release's data dictionary before going further.

WhatWhereWhere to find the value
The three business unit namesbu_map in EMPLOYEES, PAYEES, BUSINESS_TRIPS, QUICK_PAYSAlready filled in: IPP BU, FPP BU and APP BU, read from the test pod on 22 Oct 2026. Change them only if production uses different names.

2Create a report (repeat for each of the seven)

  1. Folder. Reports and Analytics → Browse Catalog → Shared Folders → Custom → New → Folder ExpenseHub. This is done once.
  2. Data model. New → Data Model. Set the Default Data Source to the one in the table above.
  3. Data set. New Data Set → SQL Query. Name it after the report (for example EH_HCM_EMPLOYEES), choose the same data source and Standard SQL, and paste the SQL from section 5. Do not add a closing semicolon. When BI Publisher asks whether to create the bind parameters, answer Yes.
  4. Parameters. Open each parameter. Set Data Type String, Parameter Type Text, and leave the default value blank. Keep the name exactly as it is (P_AS_OF_DATE, …).
  5. Sample data. On the Data tab, enter test values and click View, then Save As Sample Data. Save the data model as <REPORT>_DM in /Custom/ExpenseHub.
  6. Report. Click Create Report, choose Use Data Model, and pick a simple table layout that contains every column.
    • Keep each column header exactly the same as the SQL alias, in capitals with underscores (for example PERSON_ID). The layout editor may turn it into "Person Id"; if it does, rename it back. ExpenseHub reads the columns by these names.
    • Remove any totals, grouping, sorting and number formats from the layout. Every column is already text on purpose.
  7. Output. Report Properties → set Default Format to CSV and tick CSV in Output Formats. Under Formatting, use a comma as the CSV delimiter and keep the header row.
  8. Save the report as exactly EH_HCM_EMPLOYEES (and so on) in /Custom/ExpenseHub. ExpenseHub calls /Custom/ExpenseHub/<REPORT>.xdo.
Do not rename anythingExpenseHub depends on the report names, parameter names and column names exactly as written here. If something has to change, ask the ExpenseHub team first, because the code has to change too.

3Permissions

  • On the folder /Custom/ExpenseHub, open More → Permissions. Grant the role held by ERP_INTEGRATION_USER Read and Run Publisher Report, and apply it to the items inside the folder.
  • The integration user also needs a role that lets it run BI Publisher reports through the web service, for example BI Consumer or a custom role that includes it. It has already been confirmed (19 Oct 2026) that the user can reach the report service.
  • The data models read tables directly, so HCM data roles do not filter them. The filter on the three business units keeps the output to ZPI employees.
No bank detailsEH_AP_EMPLOYEE_PAYEES returns Y/N flags only. Never add IBANs, account numbers or bank names to it, or to any other ExpenseHub report.

4Test

  1. In Fusion: open each report and run it with test values, for example P_FROM_DATE a year ago and P_ABSENCE_TYPES = Business Trip. Check the CSV header row against the column list in the SQL.
  2. From ExpenseHub: the ExpenseHub team runs npm run fusion:bip-check. It calls all seven reports exactly as the nightly jobs do and reports, for each one: row count, counts per BU or segment, missing or unexpected columns, and any row that breaks the format (dates, amounts, flags). It never prints names or other row data.
  3. Trip destination: npm run fusion:bip-check EH_HCM_BUSINESS_TRIPS --show-fields lists each leave-request field, how many trips fill it, and a few sample values. The field that holds the destination (for example ATTRIBUTE3) goes into the ExpenseHub option Trip destination field. Your admin can also read it from the absence descriptive flexfield setup: each segment shows its table column.
  4. Sense checks:
    • EMPLOYEES has about 170 rows across IPP, FPP and APP, and nearly all of them have a line manager and a default expense account.
    • PAYEES has one row per employee.
    • SEGMENT_VALUES returns all six segments.
    • INVOICE_PAYMENTS returns nothing without invoice ids. That is correct.
ExpenseHub protects itselfIf a report returns no rows, or fewer than half of the previous night's rows, the sync stops without changing anything and shows an error on the integration monitor. A broken report cannot wipe the employee list.

5The SQL

One data set per report. Each header comment gives the catalog path, the data source, the parameters, and the EDIT and VERIFY points.

EH_HCM_EMPLOYEESEmployees, supervisor, BU, default account
-- ============================================================================================
-- EH_HCM_EMPLOYEES — INT-01/02/03: employees, supervisor, BU, default expense account
-- Catalog:     /Custom/ExpenseHub/EH_HCM_EMPLOYEES.xdo        Data source: ApplicationDB_HCM
-- Parameter:   P_AS_OF_DATE  (Text, YYYY-MM-DD; blank = today)
-- Run by:      ExpenseHub nightly 01:00 (full extract — an employee missing here is deactivated)
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  hcmEmployeeCsv
--
-- EDIT before use:  the three business unit names in bu_map (exactly as in Fusion).
-- VERIFY in the test pod: phone types for mobile (WM/HM), location table.
-- ============================================================================================
WITH params AS (
  SELECT NVL(TO_DATE(:P_AS_OF_DATE, 'YYYY-MM-DD'), TRUNC(SYSDATE)) AS as_of FROM dual
),
bu_map AS (                                                    -- Fusion BU names (read from the test pod, 22 Oct 2026)
  SELECT 'IPP BU' AS bu_name, 'IPP' AS bu_code FROM dual UNION ALL
  SELECT 'FPP BU',            'FPP'            FROM dual UNION ALL
  SELECT 'APP BU',            'APP'            FROM dual
)
SELECT
  TO_CHAR(papf.person_id)                                         AS PERSON_ID,
  papf.person_number                                              AS PERSON_NUMBER,
  ppnf.display_name                                               AS FULL_NAME,
  pea.email_address                                               AS EMAIL,
  ( SELECT MAX(NVL2(ph.country_code_number, '+' || ph.country_code_number, NULL) || ph.phone_number)
             KEEP (DENSE_RANK FIRST ORDER BY DECODE(ph.phone_type, 'WM', 1, 2))
      FROM per_phones ph
     WHERE ph.person_id = papf.person_id
       AND ph.phone_type IN ('WM', 'HM')                          -- VERIFY: work / home mobile
       AND prm.as_of BETWEEN NVL(ph.date_from, prm.as_of) AND NVL(ph.date_to, prm.as_of)
  )                                                               AS MOBILE,
  TO_CHAR(paam.assignment_id)                                     AS ASSIGNMENT_ID,
  bm.bu_code                                                      AS BU_CODE,
  pj.name                                                         AS JOB_NAME,
  ( SELECT MAX(hla.location_code) FROM hr_locations_all hla
     WHERE hla.location_id = paam.location_id )                   AS LOCATION_CODE,
  TO_CHAR(pasf.manager_id)                                        AS SUPERVISOR_PERSON_ID,
  CASE WHEN gcc.code_combination_id IS NOT NULL THEN
    gcc.segment1 || '.' || gcc.segment2 || '.' || gcc.segment3 || '.' ||
    gcc.segment4 || '.' || gcc.segment5 || '.' || gcc.segment6
  END                                                             AS DEFAULT_EXPENSE_ACCOUNT,
  CASE WHEN paam.assignment_status_type = 'ACTIVE' THEN 'Y' ELSE 'N' END AS ACTIVE_FLAG
FROM params prm
JOIN per_all_people_f papf
  ON prm.as_of BETWEEN papf.effective_start_date AND papf.effective_end_date
JOIN per_person_names_f ppnf
  ON  ppnf.person_id = papf.person_id
  AND ppnf.name_type = 'GLOBAL'
  AND prm.as_of BETWEEN ppnf.effective_start_date AND ppnf.effective_end_date
JOIN per_all_assignments_m paam
  ON  paam.person_id = papf.person_id
  AND paam.assignment_type = 'E'                                  -- employee assignments only
  AND paam.primary_flag = 'Y'
  AND paam.effective_latest_change = 'Y'
  AND prm.as_of BETWEEN paam.effective_start_date AND paam.effective_end_date
JOIN fun_all_business_units_v bu
  ON  bu.bu_id = paam.business_unit_id
JOIN bu_map bm
  ON  bm.bu_name = bu.bu_name                                     -- only IPP / FPP / APP people
LEFT JOIN per_email_addresses pea
  ON  pea.email_address_id = papf.primary_email_id
LEFT JOIN per_jobs_f_tl pj
  ON  pj.job_id = paam.job_id
  AND pj.language = USERENV('LANG')
  AND prm.as_of BETWEEN pj.effective_start_date AND pj.effective_end_date
LEFT JOIN per_assignment_supervisors_f pasf
  ON  pasf.assignment_id = paam.assignment_id
  AND pasf.manager_type = 'LINE_MANAGER'
  AND pasf.primary_flag = 'Y'
  AND prm.as_of BETWEEN pasf.effective_start_date AND pasf.effective_end_date
LEFT JOIN gl_code_combinations gcc
  ON  gcc.code_combination_id = paam.default_code_comb_id
ORDER BY papf.person_number
EH_AP_EMPLOYEE_PAYEESSupplier, site and bank flags per employee
-- ============================================================================================
-- EH_AP_EMPLOYEE_PAYEES — INT-07: can this employee be paid through Payables?
-- Catalog:     /Custom/ExpenseHub/EH_AP_EMPLOYEE_PAYEES.xdo   Data source: ApplicationDB_FSCM
-- Parameters:  none
-- Run by:      ExpenseHub nightly 01:00, right after EH_HCM_EMPLOYEES
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  apPayeeCsv
--
-- D-47: the employee's supplier is the one whose EMPLOYEE_ID is the person, else the supplier
-- named exactly like the employee (unique names only — Finance's 10035–10038 have no employee
-- link); site <BU>-EMP or any pay site in the BU. Supplier numbers are NOT person numbers.
-- Returns FLAGS ONLY. Never add bank account numbers, IBANs or bank names to this report.
--
-- EDIT before use:  the three business unit names in bu_map (same as EH_HCM_EMPLOYEES).
-- VERIFY in the test pod: POZ_SUPPLIERS.END_DATE_ACTIVE, POZ_SITE_ASSIGNMENTS_ALL_M.BU_ID,
--                         the IBY payee / instrument tables.
-- ============================================================================================
WITH params AS (
  SELECT TRUNC(SYSDATE) AS as_of FROM dual
),
bu_map AS (                                                    -- Fusion BU names (read from the test pod, 22 Oct 2026)
  SELECT 'IPP BU' AS bu_name, 'IPP' AS bu_code FROM dual UNION ALL
  SELECT 'FPP BU',            'FPP'            FROM dual UNION ALL
  SELECT 'APP BU',            'APP'            FROM dual
),
emp AS (
  SELECT papf.person_id, papf.person_number, bm.bu_code, bu.bu_id,
         UPPER(TRIM(ppnf.display_name))                                   AS name_key,
         COUNT(*) OVER (PARTITION BY UPPER(TRIM(ppnf.display_name)))      AS same_name
    FROM params prm
    JOIN per_all_people_f papf
      ON prm.as_of BETWEEN papf.effective_start_date AND papf.effective_end_date
    JOIN per_person_names_f ppnf
      ON  ppnf.person_id = papf.person_id
      AND ppnf.name_type = 'GLOBAL'
      AND prm.as_of BETWEEN ppnf.effective_start_date AND ppnf.effective_end_date
    JOIN per_all_assignments_m paam
      ON  paam.person_id = papf.person_id
      AND paam.assignment_type = 'E'
      AND paam.primary_flag = 'Y'
      AND paam.effective_latest_change = 'Y'
      AND prm.as_of BETWEEN paam.effective_start_date AND paam.effective_end_date
    JOIN fun_all_business_units_v bu ON bu.bu_id = paam.business_unit_id
    JOIN bu_map bm                   ON bm.bu_name = bu.bu_name
),
candidates AS (
  SELECT e.person_id,
         e.bu_code,
         e.bu_id,
         ps.party_id,
         ps.segment1                 AS supplier_number,
         ps.end_date_active          AS supplier_end_date,
         site.vendor_site_id,
         site.vendor_site_code,
         site.inactive_date          AS site_inactive_date,
         -- D-47: the supplier linked to the person (EMPLOYEE_ID) wins; then a site named
         -- <BU>-EMP; then any pay site in the employee's BU.
         ROW_NUMBER() OVER (
           PARTITION BY e.person_id
           ORDER BY CASE WHEN ps.employee_id = e.person_id THEN 0
                         WHEN ps.vendor_id IS NOT NULL THEN 1 ELSE 2 END,
                    CASE WHEN site.vendor_site_code = e.bu_code || '-EMP' THEN 0
                         WHEN site.vendor_site_id IS NOT NULL THEN 1 ELSE 2 END,
                    site.vendor_site_id
         )                           AS rn
    FROM emp e
    CROSS JOIN params prm
    -- D-47: the supplier's employee link; otherwise a supplier whose name is exactly this
    -- employee's full name, and only when no other employee has that name. Never the supplier
    -- number (12 ordinary suppliers share person numbers).
    LEFT JOIN hz_parties hp
      ON  e.same_name = 1
      AND UPPER(TRIM(hp.party_name)) = e.name_key
    LEFT JOIN poz_suppliers ps
      ON  ps.employee_id = e.person_id
       OR (ps.employee_id IS NULL AND ps.party_id = hp.party_id)
    LEFT JOIN poz_supplier_sites_all_m site
      ON  site.vendor_id = ps.vendor_id
      AND site.pay_site_flag = 'Y'
      AND prm.as_of BETWEEN site.effective_start_date AND site.effective_end_date
      AND (site.vendor_site_code = e.bu_code || '-EMP' OR site.prc_bu_id = e.bu_id)
),
payee AS (
  SELECT * FROM candidates WHERE rn = 1
)
SELECT
  TO_CHAR(p.person_id)                                            AS PERSON_ID,
  p.supplier_number                                               AS SUPPLIER_NUMBER,
  p.vendor_site_code                                              AS SUPPLIER_SITE,
  p.bu_code                                                       AS BU_CODE,
  CASE
    WHEN p.vendor_site_id IS NOT NULL
     AND NVL(p.supplier_end_date,  prm.as_of + 1) > prm.as_of
     AND NVL(p.site_inactive_date, prm.as_of + 1) > prm.as_of
     AND EXISTS (                                               -- site assigned to the BU
           SELECT 1
             FROM poz_site_assignments_all_m psa
            WHERE psa.vendor_site_id = p.vendor_site_id
              AND psa.bu_id = p.bu_id                           -- VERIFY: client BU column
              AND NVL(psa.inactive_date, prm.as_of + 1) > prm.as_of)
    THEN 'Y' ELSE 'N'
  END                                                             AS SITE_ACTIVE_FLAG,
  CASE
    WHEN p.party_id IS NOT NULL
     AND EXISTS (                                               -- an active disbursement bank account
           SELECT 1
             FROM iby_external_payees_all iep
             JOIN iby_pmt_instr_uses_all ipiu
               ON  ipiu.ext_pmt_party_id = iep.ext_payee_id
               AND ipiu.instrument_type  = 'BANKACCOUNT'
               AND ipiu.payment_flow     = 'DISBURSEMENTS'
               AND prm.as_of BETWEEN NVL(ipiu.start_date, prm.as_of) AND NVL(ipiu.end_date, prm.as_of)
             JOIN iby_ext_bank_accounts ieba
               ON  ieba.ext_bank_account_id = ipiu.instrument_id
               AND prm.as_of BETWEEN NVL(ieba.start_date, prm.as_of) AND NVL(ieba.end_date, prm.as_of)
            WHERE iep.payee_party_id = p.party_id
              AND (iep.supplier_site_id IS NULL OR iep.supplier_site_id = p.vendor_site_id))
    THEN 'Y' ELSE 'N'
  END                                                             AS HAS_ACTIVE_BANK_FLAG
FROM payee p
CROSS JOIN params prm
ORDER BY p.person_id
EH_GL_SEGMENT_VALUESChart-of-accounts segment values
-- ============================================================================================
-- EH_GL_SEGMENT_VALUES — INT-04: values of the 6 chart-of-accounts segments
-- Catalog:     /Custom/ExpenseHub/EH_GL_SEGMENT_VALUES.xdo    Data source: ApplicationDB_FSCM
-- Parameters:  none
-- Run by:      ExpenseHub nightly 01:30 (full extract — a value missing here is disabled)
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  glSegmentValueCsv
--
-- COA (D-12): Company.Location.CostCenter.Account.000.000000, e.g. IPP.003.127.55251.000.000000
--
-- Value set codes: read from the test pod (see seg_map); Segment 6 = Detailed_ledger.
-- VERIFY in the test pod: FND_VS_VALUES_B.SUMMARY_FLAG (parent values are left out).
-- ============================================================================================
WITH seg_map AS (                                              -- EDIT: value set codes
  -- Read from the test pod on 22 Oct 2026 (value sets holding IPP / 003 / 127 / 55251 / 000).
  SELECT 'COMPANY'     AS segment, 'ZPI_Company'    AS value_set_code FROM dual UNION ALL
  SELECT 'LOCATION',               'ZPI_Location'                     FROM dual UNION ALL
  SELECT 'COST_CENTER',            'ZPI_CostCentre'                   FROM dual UNION ALL
  SELECT 'ACCOUNT',                'ZPI_Account'                      FROM dual UNION ALL
  SELECT 'SEGMENT5',               'ZPI_Product'                      FROM dual UNION ALL
  -- Segment 6 = Detailed ledger (Finance, 23 Oct 2026; default value 0000000).
  SELECT 'SEGMENT6', vs.value_set_code
    FROM fnd_vs_value_sets vs
   WHERE UPPER(vs.value_set_code) = 'ZPI_DETAILED_LEDGER'
)
SELECT
  sm.segment                                                      AS SEGMENT,
  v.value                                                         AS VALUE,
  NVL(tl.description, tl.translated_value)                        AS DESCRIPTION,
  NVL(v.enabled_flag, 'N')                                        AS ENABLED_FLAG,
  TO_CHAR(v.start_date_active, 'YYYY-MM-DD')                      AS START_DATE,
  TO_CHAR(v.end_date_active,   'YYYY-MM-DD')                      AS END_DATE
FROM seg_map sm
JOIN fnd_vs_value_sets vs
  ON  vs.value_set_code = sm.value_set_code
JOIN fnd_vs_values_b v
  ON  v.value_set_id = vs.value_set_id
LEFT JOIN fnd_vs_values_tl tl
  ON  tl.value_id = v.value_id
  AND tl.language = USERENV('LANG')
WHERE NVL(v.summary_flag, 'N') = 'N'                              -- postable (child) values only
ORDER BY sm.segment, v.value
EH_HCM_BUSINESS_TRIPSApproved business leave requests, all fields
-- ============================================================================================
-- EH_HCM_BUSINESS_TRIPS — INT-05a: approved business leave requests (D-09, D-11, D-46)
-- Catalog:     /Custom/ExpenseHub/EH_HCM_BUSINESS_TRIPS.xdo   Data source: ApplicationDB_HCM
-- Parameters:  P_ABSENCE_TYPES  (Text, comma-separated absence type names, e.g. Business Trip)
--              P_FROM_DATE      (Text, YYYY-MM-DD; ExpenseHub sends today − 365)
-- Run by:      ExpenseHub nightly 02:00 + on demand
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  businessTripCsv
--
-- D-46: the destination is entered on the business leave request. Rather than guess which field
-- holds it, this report returns EVERY field of the request (ATTRIBUTE_CATEGORY, ATTRIBUTE1…30). ExpenseHub reads the destination from the field named in
-- its option TRIP_DESTINATION_FIELD (e.g. ATTRIBUTE3); the other fields are ignored.
-- `npm run fusion:bip-check EH_HCM_BUSINESS_TRIPS --show-fields` shows which field is filled.
-- DURATION_DAYS = calendar days, start and end inclusive.
--
-- EDIT before use:  bu_map (same as EH_HCM_EMPLOYEES).
-- Checked in the test pod (22 Oct 2026): ANC_PER_ABS_ENTRIES has no ABSENCE_REASON_ID here, so
-- the reason and comments are not returned; the ATTRIBUTE columns are the leave request's fields.
-- ============================================================================================
WITH params AS (
  SELECT NVL(TO_DATE(:P_FROM_DATE, 'YYYY-MM-DD'), TRUNC(SYSDATE) - 365) AS from_date,
         ',' || NVL(:P_ABSENCE_TYPES, 'Business Trip') || ','            AS type_list
    FROM dual
),
bu_map AS (                                                    -- Fusion BU names (read from the test pod, 22 Oct 2026)
  SELECT 'IPP BU' AS bu_name FROM dual UNION ALL
  SELECT 'FPP BU'             FROM dual UNION ALL
  SELECT 'APP BU'             FROM dual
)
SELECT
  TO_CHAR(apae.per_absence_entry_id)                              AS ABSENCE_ENTRY_ID,
  TO_CHAR(apae.person_id)                                         AS PERSON_ID,
  aat.name                                                        AS ABSENCE_TYPE,
  TO_CHAR(TRUNC(apae.start_date), 'YYYY-MM-DD')                   AS START_DATE,
  TO_CHAR(TRUNC(apae.end_date),   'YYYY-MM-DD')                   AS END_DATE,
  TO_CHAR(TRUNC(apae.end_date) - TRUNC(apae.start_date) + 1)      AS DURATION_DAYS,
  apae.approval_status_cd                                         AS APPROVAL_STATUS,
  -- Every field of the business leave request (D-46) ------------------------------------------
  apae.attribute_category                                         AS ATTRIBUTE_CATEGORY,
  apae.attribute1  AS ATTRIBUTE1,  apae.attribute2  AS ATTRIBUTE2,  apae.attribute3  AS ATTRIBUTE3,
  apae.attribute4  AS ATTRIBUTE4,  apae.attribute5  AS ATTRIBUTE5,  apae.attribute6  AS ATTRIBUTE6,
  apae.attribute7  AS ATTRIBUTE7,  apae.attribute8  AS ATTRIBUTE8,  apae.attribute9  AS ATTRIBUTE9,
  apae.attribute10 AS ATTRIBUTE10, apae.attribute11 AS ATTRIBUTE11, apae.attribute12 AS ATTRIBUTE12,
  apae.attribute13 AS ATTRIBUTE13, apae.attribute14 AS ATTRIBUTE14, apae.attribute15 AS ATTRIBUTE15,
  apae.attribute16 AS ATTRIBUTE16, apae.attribute17 AS ATTRIBUTE17, apae.attribute18 AS ATTRIBUTE18,
  apae.attribute19 AS ATTRIBUTE19, apae.attribute20 AS ATTRIBUTE20, apae.attribute21 AS ATTRIBUTE21,
  apae.attribute22 AS ATTRIBUTE22, apae.attribute23 AS ATTRIBUTE23, apae.attribute24 AS ATTRIBUTE24,
  apae.attribute25 AS ATTRIBUTE25, apae.attribute26 AS ATTRIBUTE26, apae.attribute27 AS ATTRIBUTE27,
  apae.attribute28 AS ATTRIBUTE28, apae.attribute29 AS ATTRIBUTE29, apae.attribute30 AS ATTRIBUTE30
FROM params prm
JOIN anc_per_abs_entries apae
  ON  apae.start_date >= prm.from_date
JOIN anc_absence_types_f_tl aat
  ON  aat.absence_type_id = apae.absence_type_id
  AND aat.language = USERENV('LANG')
  AND apae.start_date BETWEEN aat.effective_start_date AND aat.effective_end_date
WHERE apae.approval_status_cd = 'APPROVED'
  AND NVL(apae.absence_status_cd, 'X') <> 'ORA_WITHDRAWN'
  AND INSTR(prm.type_list, ',' || aat.name || ',') > 0
  AND EXISTS (                                                  -- only IPP / FPP / APP people
        SELECT 1
          FROM per_all_assignments_m paam
          JOIN fun_all_business_units_v bu ON bu.bu_id = paam.business_unit_id
          JOIN bu_map bm                   ON bm.bu_name = bu.bu_name
         WHERE paam.person_id = apae.person_id
           AND paam.assignment_type = 'E'
           AND paam.primary_flag = 'Y'
           AND apae.start_date BETWEEN paam.effective_start_date AND paam.effective_end_date)
ORDER BY apae.start_date, apae.per_absence_entry_id
EH_PAY_QUICK_PAYSQuickPay results to invoice
-- ============================================================================================
-- EH_PAY_QUICK_PAYS — INT-05b: QuickPays that Finance invoices through Payables (D-10, D-48)
-- Catalog:     /Custom/ExpenseHub/EH_PAY_QUICK_PAYS.xdo       Data source: ApplicationDB_HCM
-- Parameters:  P_ELEMENTS   (Text, optional comma-separated element names; blank = every QuickPay)
--              P_FROM_DATE  (Text, YYYY-MM-DD; ExpenseHub sends today − 90)
-- Run by:      ExpenseHub nightly 02:00 + on demand
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  quickPayCsv
--
-- D-48: one row per QuickPay (payroll relationship action); PAY_VALUE = its total = the sum of
-- the Standard and Supplemental Earnings it paid. That total becomes the invoice amount.
-- Key: PAYROLL_ACTION_ID + RUN_RESULT_ID (here the payroll relationship action id).
-- ============================================================================================
WITH params AS (
  SELECT NVL(TO_DATE(:P_FROM_DATE, 'YYYY-MM-DD'), TRUNC(SYSDATE) - 90) AS from_date,
         ',' || :P_ELEMENTS || ','                                      AS element_list,
         :P_ELEMENTS                                                    AS elements
    FROM dual
),
bu_map AS (                                                    -- Fusion BU names (read from the test pod, 22 Oct 2026)
  SELECT 'IPP BU' AS bu_name, 'IPP' AS bu_code FROM dual UNION ALL
  SELECT 'FPP BU',            'FPP'            FROM dual UNION ALL
  SELECT 'APP BU',            'APP'            FROM dual
),
results AS (
  SELECT ppa.payroll_action_id,
         ppra.payroll_rel_action_id,
         pprd.person_id,
         ppa.effective_date,
         pet.base_element_name,
         TO_NUMBER(prrv.result_value) AS amount
    FROM params prm
    JOIN pay_payroll_actions ppa
      ON  ppa.action_type = 'Q'                                   -- QuickPay
      AND ppa.effective_date >= prm.from_date
    JOIN pay_payroll_rel_actions ppra
      ON  ppra.payroll_action_id = ppa.payroll_action_id          -- (rolled-back ones are gone)
    JOIN pay_pay_relationships_dn pprd
      ON  pprd.payroll_relationship_id = ppra.payroll_relationship_id
    JOIN pay_run_results prr
      ON  prr.payroll_rel_action_id = ppra.payroll_rel_action_id
    JOIN pay_element_types_f pet
      ON  pet.element_type_id = prr.element_type_id
      AND ppa.effective_date BETWEEN pet.effective_start_date AND pet.effective_end_date
    JOIN pay_ele_classifications pec
      ON  pec.classification_id = pet.classification_id
      AND pec.base_classification_name IN ('Standard Earnings', 'Supplemental Earnings')
    JOIN pay_input_values_f piv
      ON  piv.element_type_id = pet.element_type_id
      AND piv.base_name = 'Pay Value'
      AND ppa.effective_date BETWEEN piv.effective_start_date AND piv.effective_end_date
    JOIN pay_run_result_values prrv
      ON  prrv.run_result_id = prr.run_result_id
      AND prrv.input_value_id = piv.input_value_id
   WHERE prm.elements IS NULL
      OR INSTR(prm.element_list, ',' || pet.base_element_name || ',') > 0
)
SELECT
  TO_CHAR(r.payroll_action_id)                                    AS PAYROLL_ACTION_ID,
  TO_CHAR(r.payroll_rel_action_id)                                AS RUN_RESULT_ID,
  TO_CHAR(r.person_id)                                            AS PERSON_ID,
  SUBSTR(LISTAGG(DISTINCT r.base_element_name, ', ' ON OVERFLOW TRUNCATE '...')
           WITHIN GROUP (ORDER BY r.base_element_name), 1, 240)   AS ELEMENT_NAME,
  TO_CHAR(ROUND(SUM(r.amount), 2), 'FM999999999990.00')           AS PAY_VALUE,
  TO_CHAR(r.effective_date, 'YYYY-MM-DD')                         AS EFFECTIVE_DATE,
  MAX(bm.bu_code)                                                 AS BU_CODE
FROM results r
JOIN per_all_assignments_m paam                                   -- BU at the effective date
  ON  paam.person_id = r.person_id
  AND paam.assignment_type = 'E'
  AND paam.primary_flag = 'Y'
  AND paam.effective_latest_change = 'Y'
  AND r.effective_date BETWEEN paam.effective_start_date AND paam.effective_end_date
JOIN fun_all_business_units_v bu
  ON  bu.bu_id = paam.business_unit_id
JOIN bu_map bm
  ON  bm.bu_name = bu.bu_name
GROUP BY r.payroll_action_id, r.payroll_rel_action_id, r.person_id, r.effective_date
HAVING ROUND(SUM(r.amount), 2) > 0
ORDER BY r.effective_date, r.payroll_action_id, r.payroll_rel_action_id
EH_AP_INVOICE_PAYMENTSPayments of ExpenseHub invoices
-- ============================================================================================
-- EH_AP_INVOICE_PAYMENTS — INT-09: payments of the invoices ExpenseHub created
-- Catalog:     /Custom/ExpenseHub/EH_AP_INVOICE_PAYMENTS.xdo  Data source: ApplicationDB_FSCM
-- Parameter:   P_INVOICE_IDS  (Text, comma-separated Fusion InvoiceIds, e.g. 300000050001,300000050002)
-- Run by:      ExpenseHub hourly 07:00–20:00, for invoices it is waiting on
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  invoicePaymentCsv
--
-- STATUS is the payment status (NEGOTIABLE, CLEARED, RECONCILED, VOIDED, …). ExpenseHub ignores
-- VOIDED payments and takes the latest of the others, so rows are ordered by payment date.
-- No parameter → no rows.
-- ============================================================================================
WITH ids AS (
  SELECT TO_NUMBER(TRIM(REGEXP_SUBSTR(:P_INVOICE_IDS, '[^,]+', 1, LEVEL))) AS invoice_id
    FROM dual
 CONNECT BY REGEXP_SUBSTR(:P_INVOICE_IDS, '[^,]+', 1, LEVEL) IS NOT NULL
)
SELECT
  TO_CHAR(aip.invoice_id)                                         AS INVOICE_ID,
  TO_CHAR(aca.check_number)                                       AS PAYMENT_NUMBER,
  TO_CHAR(aca.check_date, 'YYYY-MM-DD')                           AS PAYMENT_DATE,
  TO_CHAR(aip.amount, 'FM999999999990.00')                        AS AMOUNT,
  aca.status_lookup_code                                          AS STATUS
FROM ids
JOIN ap_invoice_payments_all aip
  ON  aip.invoice_id = ids.invoice_id
JOIN ap_checks_all aca
  ON  aca.check_id = aip.check_id
ORDER BY aip.invoice_id, aca.check_date, aip.invoice_payment_id
EH_GL_DAILY_RATESDaily conversion rates to SAR
-- ============================================================================================
-- EH_GL_DAILY_RATES — INT-06: daily conversion rates to SAR (the REST fallback, INTEGRATION §4)
-- Catalog:     /Custom/ExpenseHub/EH_GL_DAILY_RATES.xdo       Data source: ApplicationDB_FSCM
-- Parameters:  P_TO_CURRENCY (Text, default SAR) · P_RATE_TYPE (Text, e.g. Corporate; blank = all)
--              P_FROM_DATE   (Text, YYYY-MM-DD; ExpenseHub sends yesterday, or −365 days on first run)
-- Run by:      ExpenseHub daily 06:00
-- Contract:    apps/api/src/integrations/fusion/contracts.ts  glDailyRateCsv
--
-- Why a report: the currencyRates REST resource in this pod cannot be filtered (23 Oct 2026).
-- ============================================================================================
SELECT
  gdr.from_currency                                               AS FROM_CURRENCY,
  gdr.to_currency                                                 AS TO_CURRENCY,
  gdct.user_conversion_type                                       AS RATE_TYPE,
  TO_CHAR(gdr.conversion_date, 'YYYY-MM-DD')                      AS RATE_DATE,
  TO_CHAR(gdr.conversion_rate, 'FM999999990.00000000')            AS RATE
FROM gl_daily_rates gdr
JOIN gl_daily_conversion_types gdct
  ON  gdct.conversion_type = gdr.conversion_type
WHERE gdr.to_currency = NVL(:P_TO_CURRENCY, 'SAR')
  AND gdr.conversion_date >= NVL(TO_DATE(:P_FROM_DATE, 'YYYY-MM-DD'), TRUNC(SYSDATE) - 365)
  AND (:P_RATE_TYPE IS NULL OR gdct.user_conversion_type = :P_RATE_TYPE)
  AND gdr.conversion_rate > 0
ORDER BY gdr.from_currency, gdr.conversion_date
