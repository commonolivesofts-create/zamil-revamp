## 2. Common rules (apply to every interface)

1. **Credentials:** dedicated integration user, least privilege; secrets from `.env`/`secrets/` only.
2. **Mock mode:** `FUSION_MODE=mock` returns fixtures from `apps/api/src/integrations/fusion/mock/`; each interface must have a fixture with ≥ 3 rows including one edge case.
3. **Logging:** every call → `EH_INTEGRATION_LOG` (secrets stripped).
4. **Retry:** first call + up to 3 retries (waits 2 s, 10 s, 30 s; `FUSION_RETRY_DELAYS_MS`) on network errors, 429 and 5xx. Never retry 4xx except 429. After 3 failures: status `ERROR`, shown in integration monitor, Finance/Admin notified.
5. **Inbound sync is upsert + deactivate:** rows present → insert/update; rows missing from a *full* extract → `active='N'` (employees) or deleted (rates never deleted). A sync that returns **0 rows** or fewer than 50 % of the previous count **aborts without changes** and raises an error (protects against a broken report wiping data). "Previous" = rows read by the last successful run. The guard applies to the full extracts (employees, COA); the windowed extracts (trips, last 365 days; Quick Pays, last 90 days) and incremental rates rise and fall naturally and are not guarded. A trip that leaves the extract inside its window is marked `WITHDRAWN`; COA values missing from the extract are disabled, never deleted.
6. **Outbound is idempotent:** before every POST, query Fusion by invoice number; if found, store its id and do not POST.
7. **Timezone:** Fusion timestamps parsed as UTC, stored as `TIMESTAMP WITH TIME ZONE`.

## 4. Inbound interfaces

### INT-01/02/03 — `EH_HCM_EMPLOYEES`
Source tables [VERIFY]: `PER_ALL_PEOPLE_F`, `PER_PERSON_NAMES_F` (GLOBAL), `PER_EMAIL_ADDRESSES` (W1), `PER_ALL_ASSIGNMENTS_M` (primary, effective, `ASSIGNMENT_TYPE='E'`), `PER_ASSIGNMENT_SUPERVISORS_F` (LINE_MANAGER), `FUN_ALL_BUSINESS_UNITS_V` (BU), `HR_LOCATIONS_ALL_F`, `GL_CODE_COMBINATIONS` via assignment `DEFAULT_CODE_COMB_ID`.

| CSV column | → EH_EMPLOYEES |
|---|---|
| PERSON_ID | person_id |
| PERSON_NUMBER | person_number |
| FULL_NAME | full_name |
| EMAIL | email |
| MOBILE | mobile |
| ASSIGNMENT_ID | assignment_id |
| BU_CODE | business_unit (map BU name → IPP/FPP/APP in config) |
| JOB_NAME | job_name |
| LOCATION_CODE | location_code |
| SUPERVISOR_PERSON_ID | supervisor_id |
| DEFAULT_EXPENSE_ACCOUNT | default_expense_account (concatenated segments with `.`) |
| ACTIVE_FLAG | active |

Parameter `P_AS_OF_DATE` = today. Exceptions report (FR-SET-02) = active employees with null supervisor, null default account, or `payee_ok='N'`.

### INT-04 — `EH_GL_SEGMENT_VALUES`
Source [VERIFY]: `FND_VS_VALUES_B` / `FND_VS_VALUES_TL` / `FND_VS_VALUE_SETS` for the 6 value sets of the ZPI COA (names → OQ-14).
CSV: `SEGMENT` (one of COMPANY, LOCATION, COST_CENTER, ACCOUNT, SEGMENT5, SEGMENT6), `VALUE`, `DESCRIPTION`, `ENABLED_FLAG`, `START_DATE`, `END_DATE`.
Note: ExpenseHub checks each segment value; **cross-validation rules are checked by Fusion** at invoice creation. Optional improvement: validate the full combination with REST `accountCombinationsLOV` [VERIFY] before sending.

### INT-05a — `EH_HCM_BUSINESS_TRIPS` (OQ-10 → D-46)
Source [VERIFY]: `ANC_PER_ABS_ENTRIES`, `ANC_ABSENCE_TYPES_F_TL`; filter absence types from system option `TRIP_ABSENCE_TYPES`, `APPROVAL_STATUS_CD='APPROVED'`, `ABSENCE_STATUS_CD <> 'ORA_WITHDRAWN'`, start date ≥ today − 365; only people whose primary assignment is in IPP/FPP/APP.
CSV: `ABSENCE_ENTRY_ID`, `PERSON_ID`, `ABSENCE_TYPE`, `START_DATE`, `END_DATE`, `DURATION_DAYS`, `APPROVAL_STATUS`, plus **every field of the business leave request**: `ABSENCE_REASON`, `COMMENTS`, `ATTRIBUTE_CATEGORY`, `ATTRIBUTE1` … `ATTRIBUTE30`.
D-46: the sync copies the field named by option `TRIP_DESTINATION_FIELD` (e.g. `ATTRIBUTE3`) into `destination`; a name the report does not have fails the sync. Find the field with `npm run fusion:bip-check EH_HCM_BUSINESS_TRIPS --show-fields`. No location class (D-45).

### INT-05b — `EH_PAY_QUICK_PAYS` (OQ-07)
Source [VERIFY]: `PAY_PAYROLL_ACTIONS` (QuickPay action type), `PAY_PAYROLL_REL_ACTIONS`, `PAY_RUN_RESULTS`, `PAY_RUN_RESULT_VALUES` (Pay Value), `PAY_ELEMENT_TYPES_F` / `_TL`, `PAY_PAY_RELATIONSHIPS_DN`; filter elements from system option `QUICKPAY_ELEMENTS`; effective date ≥ today − 90 (configurable).
CSV: `PAYROLL_ACTION_ID`, `RUN_RESULT_ID`, `PERSON_ID`, `ELEMENT_NAME`, `PAY_VALUE`, `EFFECTIVE_DATE`, `BU_CODE`.
Unique key (`PAYROLL_ACTION_ID`,`RUN_RESULT_ID`). Rows already invoiced are never updated.

### INT-07 — `EH_AP_EMPLOYEE_PAYEES` (OQ-12 → D-42)
Source [VERIFY]: `POZ_SUPPLIERS` / `POZ_SUPPLIER_SITES_ALL_M` (employee-type suppliers; D-42: `SEGMENT1` supplier number = HCM person number, joined to `PER_ALL_PEOPLE_F.PERSON_NUMBER`; site `<BU>-EMP` assigned to the BU), `IBY_EXT_BANK_ACCOUNTS` via `IBY_ACCOUNT_OWNERS` / payee assignments — **output only flags, never bank details**.

## 5. Outbound — INT-08 Payables invoice

### 5.1 Trigger
`READY_FOR_PAYMENT` report (or `INVOICE_REQUESTED` Quick Pay) + Finance clicks **Send to Payables** (OQ-16 proposal B), or hourly job when `INVOICE_SEND_MODE=AUTO`. Skip if `net_payable_sar = 0` (→ `SETTLED`, OQ-13).

### 5.2 Steps
1. **Idempotency check** — `GET /fscmRestApi/resources/11.13.18.05/invoices?q=InvoiceNumber='{report_number}';Supplier='{supplier}'&onlyData=true`. If found → save id, go to step 4.
2. **Create** — `POST /fscmRestApi/resources/11.13.18.05/invoices` (payload 5.3).
3. **Save** `fusion_invoice_id` (`InvoiceId`), `fusion_invoice_num`; status → `INVOICED`; history `SENT_TO_PAYABLES`.
4. **Attach receipts** (OQ-17) — `POST …/invoices/{InvoiceId}/child/attachments` with `DatatypeCode='FILE'`, `FileName`, `FileContents` (base64), `Category` [VERIFY category name, e.g. `From Supplier`].
5. On 4xx: keep `READY_FOR_PAYMENT`, store message in `sync_error`, show in Finance list with **Retry**.

### 5.3 Payload (draft — field names [VERIFY])

```json
{
  "InvoiceNumber": "EH-IPP-2026-000123",
  "InvoiceCurrency": "SAR",
  "PaymentCurrency": "SAR",
  "InvoiceAmount": 1840.00,
  "InvoiceDate": "2026-10-20",
  "BusinessUnit": "<Fusion BU name for IPP>",
  "Supplier": "<employee supplier name>",
  "SupplierNumber": "1011",
  "SupplierSite": "IPP-EMP",
  "InvoiceType": "Standard",
  "InvoiceSource": "EXPENSEHUB",
  "Description": "Expense report EH-IPP-2026-000123 – Client visit Riyadh",
  "PaymentMethod": "EFT",
  "PayGroup": "EMPLOYEES",
  "PaymentTerms": "Immediate",
  "invoiceLines": [
    {
      "LineNumber": 1,
      "LineType": "Item",
      "LineAmount": 500.00,
      "Description": "2026-10-12 Meals – Al Baik",
      "DistributionCombination": "IPP.003.127.55251.000.000000"
    },
    {
      "LineNumber": 2,
      "LineType": "Item",
      "LineAmount": -500.00,
      "Description": "Advance ADV-IPP-2026-000007 applied",
      "DistributionCombination": "<advance clearing account, OQ-13>"
    }
  ]
}
```

Line building rules:
- One invoice line per expense line with `source=CASH` and `approved_amount_sar > 0`.
- **No VAT (D-41).** Line amount = approved amount, gross; no `TaxClassificationCode`; invoice total = Σ lines − advance. The supplier/site must have no tax applicability so Fusion Tax adds nothing [VERIFY in the test pod]. (With `VAT_RECOVERY = Y` the old behaviour returns: net lines plus `TaxClassificationCode`.)
- D-42: `PayGroup` and `PaymentTerms` are sent on every invoice [VERIFY attribute names; if the REST resource rejects them, drop them and let the supplier-site defaults apply].
- Advance applied → one negative line per advance application.
- `InvoiceAmount` = net payable.
- Card lines are **not** sent (phase 3 has a separate card-issuer invoice).

### 5.4 Quick Pay invoice
Same endpoint; `InvoiceNumber = QP-<BU>-<YYYY>-<seq>`; one line, amount = Pay Value, account from system option `ACCT_QUICKPAY_<element>` or the element's costing [VERIFY with Finance, OQ-07].

## 6. Inbound — INT-09 Invoice and payment status

Every hour for reports in `INVOICED` (and Quick Pays in `INVOICED`):
```
GET /fscmRestApi/resources/11.13.18.05/invoices/{InvoiceId}
    ?fields=InvoiceId,InvoiceNumber,ValidationStatus,ApprovalStatus,PaidStatus,CanceledFlag,AmountPaid&onlyData=true
```
[VERIFY attribute names]. Then for `PaidStatus` = Paid / Partially paid, get the payment number and date via BIP `EH_AP_INVOICE_PAYMENTS` (source [VERIFY]: `AP_INVOICE_PAYMENTS_ALL`, `AP_CHECKS_ALL`; CSV `INVOICE_ID`, `PAYMENT_NUMBER`, `PAYMENT_DATE`, `AMOUNT`, `STATUS`), or REST `payablesPayments` if available in your release.

| Fusion result | ExpenseHub action |
|---|---|
| Validated / not paid | update `fusion_status` only |
| Fully paid | `payment_ref`, `paid_at`, status → `PAID`, notify employee |
| Partially paid | `fusion_status = PARTIALLY_PAID`, Finance flag |
| Cancelled | status → `READY_FOR_PAYMENT`, `sync_error='Cancelled in Fusion'`, Finance flag (OQ-18) |
| Payment voided | status → `INVOICED`, clear `payment_ref`, Finance flag |

### 6.1 As built in M7 (mock mode, D-36)
- `EH_AP_INVOICE_PAYMENTS` takes `P_INVOICE_IDS` (comma-separated `InvoiceId`s of the invoices polled) — one BIP call per INT-09 run.
- INT-09 polls `INVOICED` reports / Quick Pays and `PAID` ones paid in the last 30 days (to catch voided payments).
- A cancelled invoice is not reused by the idempotency check; sending again creates a new invoice with the same number [VERIFY Fusion allows this after cancellation — else OQ-18 needs a suffix rule].
- Mock Fusion keeps its invoices in `FUSION_MOCK_STATE` (`storage/mock-fusion.json`, cleared by `npm run data:reset`), rejects a missing supplier or a duplicate open invoice number with HTTP 400, and is driven by the dev **Fusion simulator** page (validate / pay / cancel / void, auto-advance, fail the next send).
- Amounts are exact halalas until the payload; JSON numbers are written from the 2-decimal string.
