Setting up employees as suppliers

ExpenseHub pays approved expense claims and Quick Pays through Oracle Fusion Payables. Because Fusion Expenses is not licensed, every employee who claims must exist as a Payables supplier with a site in their business unit and an active bank account. This guide covers the one-time setup, the record for each employee, a bulk load, and how to check the result.

For: Finance (AP) and the Fusion administrator Version 1 · 19 Oct 2026 Decisions D-40, D-41, D-42

1One-time setup

Do these once, in the test pod first and then in production. All tasks are under Setup and Maintenance → search the task name.

#WhatTask / whereValue
1.1Payment termsManage Payment TermsImmediate (normally seeded). Check that it is assigned to the reference data set used by the IPP, FPP and APP business units.
1.2Payment methodManage Payment Methods (Disbursements)Electronic (code EFT). Check that its usage rules allow the three business units, and that a payment process profile exists for SAR bank transfers. VERIFY
1.3Pay groupManage Payables Lookups → lookup type PAY GROUPAdd EMPLOYEES, meaning "Employee expense reimbursements". Payment process requests can then select employee payments on their own.
1.4Invoice sourceManage Payables Lookups → lookup type SOURCEAdd EXPENSEHUB, meaning "ExpenseHub expense claims". ExpenseHub sets this source on every invoice it creates.
1.5Supplier numberingSpecify Supplier Numbering (Procurement) VERIFYThe supplier number must equal the person number. The supplier page usually generates numbers automatically. The supplier import (section 3) is the safe way to set your own number. See the note below.
1.6Banks and branchesManage Banks, Manage Bank BranchesEvery bank the employees use (SAB, SNB, Al Rajhi, Riyad Bank, …) needs a bank and a branch record before an IBAN can be added.
1.7Integration userSecurity ConsoleERP_INTEGRATION_USER needs to create and query Payables invoices, add attachments and run BI reports in /Custom/ExpenseHub.
Supplier number = person numberFusion supplier numbers share one sequence across all suppliers. Before loading, check that no existing supplier already has a number equal to an employee's person number. Also set the next automatic number above the highest person number, so normal suppliers never collide with employees. If Fusion will not accept your own numbers, tell the ExpenseHub team: the fallback is to put the person number in the supplier's Alternate Name, and ExpenseHub will match on that instead. VERIFY

2.4 Bank account (payee)

On the supplier: Payments → Bank Accounts → Create. Add the country, bank, branch, account number and IBAN (SA + 22 digits). Assign the account at the supplier level, or at the site, as the primary account.

The employee's payroll account already exists: link it, don't create itEmployees paid through HCM payroll already have their bank account in Fusion, so Create Bank Account fails with "A record with this combination of values already exists". Instead, add the supplier as a joint owner of that existing account and assign it as the supplier's primary payment account. This is how the test suppliers 10023 and 10035–10038 were set up on 24 Oct 2026, through the Fusion REST API (external bank account owners plus instrument assignments). One account then serves both payroll and Payables.
Bank data is sensitiveTake IBANs from the payroll bank list or the employee's signed bank letter. Never take them from email. Do not send spreadsheets with IBANs by email or Teams. ExpenseHub never stores or shows bank details. It only receives a yes/no flag saying that an active bank account exists.

3Bulk load for all ~170 employees (recommended)

Loading by file is faster and is the reliable way to set supplier numbers. Use the File-Based Data Import (FBDI) templates for suppliers from the Oracle Help Center (File-Based Data Import for Procurement), and use the template for your release. VERIFY

  1. Export the employee list from HCM (person number, name, BU, bank details from payroll). The ExpenseHub employee report EH_HCM_EMPLOYEES can provide the first three columns.
  2. Fill the templates in this order. Each one is uploaded, then processed with its own scheduled process:
    OrderTemplate / interfaceKey valuesScheduled process
    1Suppliers (POZ_SUPPLIERS_INT)Name, Supplier Number = person number, Type = Employee, Business Relationship = Spend AuthorizedImport Suppliers
    2Supplier Addresses (POZ_SUP_ADDRESSES_INT)Address name, country SA, Payment purposeImport Supplier Addresses
    3Supplier Sites (POZ_SUPPLIER_SITES_INT)Procurement BU, site <BU>-EMP, Pay purpose, Pay Group EMPLOYEES, Terms Immediate, Payment Method EFTImport Supplier Sites
    4Site Assignments (POZ_SITE_ASSIGNMENTS_INT)Client BU = same BU, Bill-to BU, liability accountImport Supplier Site Assignments
    5Supplier Bank Accounts (Payments FBDI)Supplier number, site, bank, branch, IBAN, primary flagImport Supplier Bank Accounts VERIFY
  3. Run each process in Import mode, then Review its output report. Fix any rejected rows and reload only those.
  4. Interface table names and column headings differ slightly between releases. Always use the template that matches your pod. VERIFY
TipLoad 3 to 5 employees in the test pod first, run the checks in section 5, and send one test invoice from ExpenseHub. Load everyone only after that works.

4No VAT on these invoices

It is agreed that ExpenseHub invoices carry no VAT (D-41). ExpenseHub sends every line at the full amount the employee paid, with no tax classification code. Fusion must not add tax either.

  • Leave the supplier's tax registration number blank, and do not enable tax applicability on the employee sites (supplier → Transaction Tax / tax profile: Allow tax applicability unticked). VERIFY
  • Check with the tax team that no tax rule applies VAT by default to invoices from source EXPENSEHUB or from suppliers of type Employee.
  • Test: after one test invoice from ExpenseHub, open it in Payables. Total Tax must be 0, and the invoice total must equal what the employee is owed.

The VAT the employee paid stays in the expense account, which is the agreed treatment. ExpenseHub still reads the ZATCA QR on receipts, as evidence and to catch typing mistakes.

5Checks before go-live

  • Lookups exist: pay group EMPLOYEES and invoice source EXPENSEHUB.
  • Every active employee has a supplier with Supplier Number = person number and type Employee.
  • Each employee has an active site named for their BU (IPP-EMP / FPP-EMP / APP-EMP), with Pay purpose and a site assignment to that BU.
  • Each site has Pay Group EMPLOYEES, Terms Immediate, Payment Method Electronic.
  • Each employee has an active primary bank account (IBAN).
  • A test invoice from ExpenseHub validates with no tax lines, and a test payment (EFT) completes.
  • In ExpenseHub, Setup → Integration monitor → INT-07 shows every employee as a valid payee. Anyone flagged is missing a supplier, a site for their BU or a bank account.

How ExpenseHub checks this

Every night, the BI report EH_AP_EMPLOYEE_PAYEES returns one row per employee: PERSON_ID, SUPPLIER_NUMBER, SUPPLIER_SITE, BU_CODE, SITE_ACTIVE_FLAG, HAS_ACTIVE_BANK_FLAG. It returns flags only, never bank details. An employee counts as a valid payee only when all three exist. If an employee has no valid payee record, ExpenseHub does not let Finance send their claim to Payables, and shows the reason instead.

6Joiners, movers and leavers

EventWhat Finance does
New joinerCreate the supplier, site and bank account (section 2) before their first claim. ExpenseHub reports missing payees after its nightly sync.
Moves to another BUAdd a site for the new BU (for example FPP-EMP). Keep the old site active until claims already sent under the old BU are paid, then end-date it.
Changes bankAdd the new account as primary and end-date the old one. Do this after any payment already in progress has finished.
LeaverAfter the final settlement is paid, end-date the site(s) and set the supplier to inactive. Do not delete it, because its payment history must stay.
